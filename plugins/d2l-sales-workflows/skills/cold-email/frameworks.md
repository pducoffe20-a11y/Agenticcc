# Cold Email Frameworks

Use a framework only when it makes the message clearer. Freeform is fine when the draft already
flows naturally.

## Useful Shapes

- Observation -> Problem -> Proof -> Ask.
- Trigger -> Insight -> Ask.
- Question -> Value -> Ask.
- Story -> Bridge -> Ask.
- Referral -> Context -> Ask.

## D2L-Friendly Pattern

```text
[Verified context].

Teams in that spot are often trying to [buyer problem] without [tradeoff].

[One relevant proof point].

[Soft ask].
```

## Rules

- One framework per email.
- One proof point per email unless Pat asks for options.
- One CTA.
- Cut setup before cutting buyer relevance.
